# Repo Audit — July 2026 (post v1.1.1)

Scope: full audit of `gfargo/ink-playing-cards` at `62316ee` (v1.1.1). Every "Evidence"
line below was reproduced locally against the compiled `dist/` output, not inferred from
reading source.

Baseline verified during this audit:

## Part 1 — Bugs

### B1. `gameReducer` has no `default` case — an unknown action wipes GameContext state

**Severity: critical** · `src/contexts/GameContext.tsx`

The `switch` in `gameReducer` returns nothing for unrecognised actions, so the reducer
returns `undefined` and the entire game context is destroyed. TypeScript's exhaustiveness
check hides this at compile time, but nothing protects the runtime boundary (JS consumers,
typo'd action types, custom actions forwarded from a wrapper reducer).

**Evidence**

```tsx
dispatch({type: 'TOTALLY_UNKNOWN'})
// -> phase=undefined turn=undefined  (state object is gone)
```

**Fix** Add `default: return state`. Audit `deckReducer` for the same gap.

---

### B2. Reducers perform side effects — every event fires twice under StrictMode

**Severity: critical** · `src/contexts/DeckContext.tsx`

`deckReducer` calls `state.eventManager.dispatchEvent(...)` inline for `SHUFFLE`, `DRAW`,
`DEAL`, `PLAY_CARD`, `DISCARD` etc. React deliberately double-invokes reducers in
StrictMode to surface impurity, so every game event is emitted twice. Any listener with a
real consequence (draw triggers, damage, scoring, network broadcast) double-applies.

**Evidence** One `SHUFFLE` + one `DRAW` dispatch, single listener each:

```
WITHOUT StrictMode -> ["DECK_SHUFFLED","CARDS_DRAWN"]
WITH    StrictMode -> ["DECK_SHUFFLED","DECK_SHUFFLED","CARDS_DRAWN","CARDS_DRAWN"]
```

**Fix** Make the reducer pure. Accumulate a list of pending events on the returned state
(or in a ref queue) and flush them from a `useEffect` in `DeckProvider`.

---

### B3. `useDeck()` / `useHand()` silently no-op outside a provider

**Severity: high** · `src/hooks/useDeck.ts`, `src/hooks/useHand.ts`, `src/contexts/DeckContext.tsx`

Both hooks contain a `if (!context) throw new Error('... must be used within a DeckProvider')`
guard, but `createContext` is given a fully-populated default object (including module-level
`EventManager`/`EffectManager` singletons and a `dispatch: () => null` stub). The guard can
never fire. Misuse produces an empty deck and silently swallowed dispatches instead of an error.

Note this also partially reintroduces the module-level singleton sharing that #5 set out to fix —
the singletons still exist, they are just only reachable off-provider.

**Evidence**

```
useDeck() outside provider -> NO THROW. deck.length=0, shuffle() is a no-op
useHand() outside provider -> NO THROW. hand.length=0, drawCard(3) is a no-op
```

**Fix** `createContext<DeckContextType | undefined>(undefined)` and let the existing guards work.

---

### B4. Joker cards render completely blank in every variant and theme

**Severity: high** · `src/constants/cardArt.ts`, `src/components/Card/utils.ts`

`'JOKER'` is a member of `TCardValue`, but no art table has an entry for it and it has no pip
layout, so the card body renders empty. Separately, `createStandardDeck()` has no way to
include jokers at all — so the type permits a card the library cannot draw or render.

**Evidence** Render matrix over 3 variants × 6 themes × 4 suits × 14 values:

```
NO-ART by card value: {"JOKER":28}   // 28/28 joker combinations, 0 for all other values
```

```
╭─────────────╮
│JOKER ♥      │
│             │   <- 9 empty rows
│      ♥ JOKER│
╰─────────────╯
```

**Fix** Add joker art per theme; also see F7 for `createStandardDeck({jokers: n})`.

### B5. CI masks all snapshot failures

**Severity: high** · `.github/workflows/ci.yml`

CI runs `npx ava --update-snapshots`, which rewrites snapshots to match whatever the code
currently produces. Snapshot assertions therefore cannot fail in CI. Every visual regression
across 20 snapshot files passes silently. This is also why B6 has gone unnoticed.

**Fix** Run `yarn test` (plain `ava`) in CI. Commit snapshots and treat drift as a failure.

---

### B6. Snapshot tests depend on ambient color support — `yarn test` fails on a non-TTY

**Severity: high** · `package.json` (ava config)

Snapshots were recorded with ANSI color codes present. Nothing pins the color level, so when
stdout is not a TTY (piping, most CI shells, editor test runners) chalk strips color and 133
tests fail on diffs that are purely `'🂠'` vs `'\e[31m🂠\e[39m'`.

**Evidence**

```
npx ava                 -> 133 tests failed
FORCE_COLOR=1 npx ava   -> 228 tests passed
```

**Fix** Set `FORCE_COLOR=1` (or `environmentVariables` in the ava config) so results are
deterministic regardless of terminal. Pair with B5.

### B7. The published package ships its own test suite and storybook

**Severity: high** · `.npmignore`, `tsconfig.json`, `package.json`

`tsconfig.json` includes all of `src`, so `tsc` compiles test files into `dist/`. The
`.npmignore` patterns intended to exclude them (`**.test.**`, `**.test.js`) are not valid
globs for this and match nothing. Consumers download 32 test artifacts plus the entire
storybook (which imports `chalk`/`meow` — devDependencies that will not be installed).

**Evidence**

```
npm pack --dry-run -> 114 files, 335.8 kB unpacked
find dist -name '*test*' | wc -l -> 32
```

**Fix** Add a `tsconfig.build.json` that excludes `**/*.test.*` and `src/storybook`, or fix the
globs to `**/*.test.*`. Verify with `npm pack --dry-run`.

### B8. `createPairedDeck()` puts every matching pair in adjacent slots

**Severity: high** · `src/components/Deck/utils.ts`

Pairs are built, the *pair units* are shuffled, then `pairs.flat()` emits them — so matching
cards always land at indices `2n`/`2n+1`. A Memory/Concentration game built on this is
trivially winnable. Secondly, each pair is assembled from two different suits, so face-up the
two "matching" cards do not look alike.

`#12` fixed the shuffle *bias* in this function; both of these issues are separate and remain.

**Evidence**

```
first 12 values: K,K,6,6,J,J,8,8,Q,Q,6,6
26/26 pairs sit in adjacent slots
26/26 pairs have MISMATCHED suits
```

**Fix** Flatten first, then shuffle the flat array. Build pairs from the same suit (use two
half-decks) so pairs are visually identical.

### B9. `CustomCard` silently discards content that does not fit

**Severity: medium** · `src/components/CustomCard/index.tsx`

Small size presets have less inner height than the number of layout regions, and `overflow:
hidden` drops the remainder with no warning. `micro` (5×3, inner height 1) renders exactly one
region and throws away the rest.

**Evidence**

```tsx
<CustomCard size="micro" title="Long Title" cost="{3}" typeLine="Creature"
  description="..." footerLeft="3/4" footerRight="R" symbols={[...]} />
```
```
╭───╮
│Cre│    <- typeLine only; title, cost, description, footer, symbols all gone
╰───╯
```

**Fix** Document a region budget per size, prioritise regions deterministically, and warn in
development when regions are dropped.

---

### B10. `CustomCard` text wrapping drops long words and mishandles newlines

**Severity: medium** · `src/components/CustomCard/index.tsx` (`wrapText`)

`wrapText` splits on spaces only. A word longer than the line is truncated and its remainder
is lost (no hard break), and an embedded `\n` is treated as part of a word, producing a broken
ragged layout.

**Evidence**

```tsx
<CustomCard size="small" description="Supercalifragilisticexpialidocious" />
// -> "Supercalif"  (24 characters silently lost)

<CustomCard size="medium" description={'Line one\nLine two\nLine three'} />
// -> "Line one" / "Line" / "two" / "Line three"
```

**Fix** Hard-break words longer than the line; split on `\n` before wrapping.

---

### B11. `CustomCard.onClick` is public API but never wired up

**Severity: medium** · `src/types/index.ts`, `src/components/CustomCard/index.tsx`

`onClick` is declared on `CustomCardProps` and never referenced by the component. Consumers
pass a handler and nothing happens.

**Fix** Remove it, or implement it as part of the selection/focus work in F13.

---

### B12. `TarotCard` footer is not bottom-anchored and "corner symbols" are not in corners

**Severity: medium** · `src/components/TarotCard/index.tsx`, `src/components/CustomCard/index.tsx`

The footer renders inline in normal flow, so on cards whose content is shorter than the card it
appears mid-card with blank rows beneath it. `CornerSymbols` renders as a dedicated
full-width `space-between` row rather than an overlay, consuming two whole content lines — and
for Major Arcana it duplicates the numeral already shown in the footer.

**Evidence**

```
╭──────────────────╮
│⛤                 │  <- "corner" symbol row (consumes a full line)
│10 of Pentacles   │
│⛤ ⛤ ⛤ ⛤ ⛤         │
│⛤ ⛤ ⛤ ⛤ ⛤         │
│Minor Arcana      │
│⛤        Pentacles│  <- footer on line 6 of 11, not at the bottom
│                  │
│                  │  <- 4 blank lines below the footer
╰──────────────────╯
```

**Fix** Give the body region `flexGrow={1}` so the footer is pushed to the bottom; render
corner symbols overlaid on the header/footer rows instead of on their own lines.

### B13. `CardGrid` renders double the requested spacing

**Severity: medium** · `src/components/CardGrid/index.tsx`

`marginY={spacing.row}` is applied to every row and `marginX={spacing.col}` to every cell, so
adjacent margins sum and gaps are twice what the caller asked for.

**Evidence** `spacing={{row: 1, col: 1}}` produces 2 blank rows between rows and 2 spaces
between columns.

**Fix** Use `gap`, or apply the margin on one side only (e.g. `marginTop` for all rows but the
first).

---

### B14. `CardStack` vertical stacking spreads cards apart, and mini/micro get fractional margins

**Severity: medium** · `src/components/CardStack/index.tsx`

Two problems in the same expression. For `stackDirection="vertical"` the overlap is applied as
`marginTop: Math.abs(baseOverlap) * 0.5 * scale` — `Math.abs` discards the sign, so the default
`overlap: -2` *separates* the cards instead of overlapping them. And at `scale = 0.5`
(mini/micro) the result is `0.5`, a fractional margin handed straight to Yoga, producing
inconsistent gaps between cards in the same stack.

**Evidence**

```
minimal/vertical  -> one blank line between each card (expected overlap)
mini/vertical     -> gap after card 1, no gap after card 2  (marginTop = 0.5)
```

**Fix** Preserve the sign for vertical overlap and `Math.round()` all scaled margins.

---

### B15. `Deck` renders nothing when the top card is a custom card

**Severity: medium** · `src/components/Deck/index.tsx`

The component guards on `isStandardCard(topCard)` and returns `null` for anything else, but
still renders the placeholder card underneath — so a custom-card deck shows a permanently
empty-looking pile.

**Evidence** `<DeckProvider initialCards={[{id:'x1',title:'Wild'}]}><Deck showTopCard/>` renders
only the placeholder.

**Fix** Fall through to `CustomCard` the way `CardStack` already does (#5).

---

### B16. `MiniCard` value alignment, joker truncation, and ignored card back

**Severity: medium** · `src/components/MiniCard/index.tsx`

Three small defects:

1. Single-char values are centred, `'10'` is not — `│ A │` vs `│10 │`.
2. `'JOKER'` is truncated to `JOK` (and `micro` has no room at all).
3. The face-down face hardcodes `?` and ignores `backArtwork` from `DeckContext`, unlike `Card`.

Also `height: variant === 'mini' ? 4 : 4` is a no-op ternary.

**Fix** Pad/centre uniformly on display width, map `JOKER` to a short glyph, and read
`backArtwork` from context.

---

### B17. `cutDeck` does not validate its index

**Severity: medium** · `src/systems/Zones.ts`

No bounds checking, so out-of-range and non-integer inputs fail silently or wrongly.

**Evidence**

```
cutDeck(len5,  0)   -> unchanged (silent no-op)
cutDeck(len5, -2)   -> [c4,c5,c1,c2,c3]  (cuts from the end)
cutDeck(len5, 99)   -> unchanged (silent no-op)
cutDeck(len5, 2.5)  -> [c3,c4,c5,c1,c2]  (accepted by accident)
```

**Fix** Clamp/validate to `[1, length - 1]`, floor the index, and throw or no-op explicitly.

---

### B18. `TarotCardProps` is missing from the `TCard` union

**Severity: medium** · `src/types/index.ts`

`TCard = CardProps | CustomCardProps`. `createTarotDeck()` returns `TarotCardProps[]`, so the
library's own exported deck constructor cannot be passed to the library's own exported
provider without a cast — and tarot cards cannot be placed in zones, `CardStack`, or `CardGrid`.

**Fix** Add `TarotCardProps` to `TCard` and teach the zone-rendering components to dispatch on
it.

---

### B19. `center`/`left`/`right` bake in a border width, then callers subtract it again

**Severity: medium** · `src/utils/text.ts`, `src/utils/layout.ts`

`center(text, width)` computes padding from `width - 2`, hardcoding a border assumption into a
generic text helper. `formatLine` in `layout.ts` already subtracts frame and padding widths
before calling it, and `createFramedSection` then re-centres the result — so framed output is
consistently 2 columns narrower than requested. Neither module is exported or covered by tests.

**Fix** Make `center`/`left`/`right` pad to exactly `width`, move border accounting to the
callers, and add unit tests. If `layout.ts` is dead code, delete it.

---

### B20. All layout math uses `String.length` instead of display width

**Severity: medium** · throughout `src/utils`, `src/components/CustomCard`, `src/components/MiniCard`

Padding, centring, and `fit()` all use `.length`, which is wrong for wide (CJK), emoji,
combining, and ANSI-wrapped text. Any consumer using non-ASCII in a `title`, `description`, or
`asciiArt` gets misaligned borders. `string-width` is already in the dependency tree via Ink.

**Fix** Route all width math through `string-width`.

---

### B21. `EventManager` mutates its listener array mid-dispatch and has no error isolation

**Severity: medium** · `src/systems/Events.ts`

`dispatchEvent` iterates the live listener array, so a listener that removes itself (or another
listener) during dispatch causes subsequent listeners to be skipped. There is also no
`try/catch`, so one throwing listener prevents every remaining listener from running.

**Fix** Iterate a copy; wrap each `handleEvent` in `try/catch` and report failures. Consider a
`once` option while in here.

---

### B22. `EnhancedSelectInput`'s `limit` truncates the list instead of scrolling

**Severity: low** · `src/storybook/utils/EnhancedSelectInput.tsx`

`rotateIndex` is created with `useState` but only ever written, never read.
`visibleItems = filteredItems.slice(0, limit)` therefore always shows the first `limit` entries
and items beyond the limit are unreachable. The rotation logic is dead code.

Related: hotkeys are not checked against the navigation keys, so a hotkey of `h`/`j`/`k`/`l`
would both navigate and select.

**Fix** Use `rotateIndex` to window the slice, or drop `limit` and the rotation state entirely.

---

### B23. `NEXT_TURN` with zero players does modulo-by-zero

**Severity: low** · `src/contexts/GameContext.tsx`

`(currentIndex + 1) % state.players.length` is `NaN` when there are no players; the `??`
fallback masks the bad index but `turn` still advances on an empty game.

**Evidence** `<GameProvider>` with no `initialPlayers` → `turn=1 current=""`.

**Fix** Return `state` early when `players.length === 0`.

---

### B24. `RESET` clears the player roster along with the deck

**Severity: low** · `src/contexts/DeckContext.tsx`

`RESET` sets `players: []`, so starting a new round forces every player to re-register (which
currently happens implicitly via `DRAW`/`DEAL`). Resetting cards and forgetting who is playing
are different operations.

**Fix** Preserve `players` on `RESET`, or add `payload: {keepPlayers?: boolean}`.

---

### B25. `theme` is silently ignored for the `simple` and `minimal` variants

**Severity: low** · `src/components/Card/utils.ts`

`theme` is accepted on `CardProps` for all variants but only affects `variant="ascii"`.
Passing `theme="robot"` with `variant="simple"` does nothing and gives no feedback.

**Evidence** Rendering K♠ across all 6 themes:

```
variant=minimal -> 1 distinct rendering across 6 themes  (theme ignored)
variant=simple  -> 1 distinct rendering across 6 themes  (theme ignored)
variant=ascii   -> 6 distinct renderings across 6 themes  (correct)
```

**Fix** Either honour the theme where feasible or narrow the type so `theme` is only accepted
alongside `variant="ascii"`.

---

### B26. Storybook `exit` selection sets an invalid view

**Severity: low** · `src/storybook/storybook.tsx`

The `exit` branch calls `exit()` and then `setCurrentComponent('exit' as ComponentView)` — a
value outside the union, kept alive only by the cast.

**Fix** `return` after `exit()`.

---

### B27. No `packageManager` field — Yarn 4 silently migrates the v1 lockfile

**Severity: low** · `package.json`

`yarn.lock` is a Yarn 1 lockfile. On any machine where Corepack resolves a modern Yarn, `yarn
install` rewrites the lockfile, writes a `.yarnrc.yml`, and then fails
`--frozen-lockfile` — which is exactly what CI runs.

**Evidence** `yarn install --frozen-lockfile` in this sandbox: *"Migrated your project to the
latest Yarn version"* → `YN0028: The lockfile would have been modified`.

**Fix** Add `"packageManager": "yarn@1.22.22"` (or migrate deliberately to Yarn 4 and commit the
new lockfile) and pin the version in CI.

---

### B28. Stale `.npmignore`

**Severity: low** · `.npmignore`

References `prompts/` (does not exist) and duplicates rules that `files: ["dist","skills"]`
already enforces, while its actual test-exclusion globs are broken (see B7).

**Fix** Delete `.npmignore` and rely on `files`, once B7 is fixed at the tsconfig level.

## Part 2 — Features and extensions

### Foundations

**F1. Seeded, injectable RNG.** `shuffleCards` and `generateCardId` both call `Math.random()`
directly. Without a seedable source there is no way to write a deterministic shuffle test,
replay a game from a log, or keep two clients in sync in the multiplayer scenarios the examples
already describe. Accept an optional `rng: () => number` on `DeckProvider`, the shuffle
helpers, and the deck constructors.

**F2. Custom named zones.** Zones are hardcoded to `deck`, `hands`, `discardPile`, `playArea`.
Every solitaire example — klondike, pyramid, golf, aces-up, accordion — bypasses `DeckProvider`
entirely and rebuilds tableau/foundation/stock/waste in local `useState`. That is five examples
demonstrating that the library's flagship state system cannot express a whole genre. Add
`zones: Record<string, TCard[]>` with a generic `MOVE_CARD` action.

**F3. Wire the effects system into the reducer.** `EffectManager` is exposed on the context but
never invoked by `deckReducer`, so the entire effects system (implemented in #6) is inert unless
consumers call it manually. `DrawCardEffect` also mutates `gameState.zones` via `splice`,
contradicting the immutable reducer design. Decide the integration point and make effects
return new state.

**F4. `useGame()` hook.** `useDeck` and `useHand` exist, but `GameContext` requires raw
`useContext` — even `SKILL.md` documents it that way. Add the hook for parity.

**F5. Auto-reshuffle on deck exhaustion.** `DRAW` silently returns fewer cards than requested
when the deck runs dry. Nearly every real game reshuffles the discard pile back in. Add an
opt-in `reshuffleWhenEmpty` behaviour and a `DECK_EXHAUSTED` event.

**F6. Player management.** `GameContext` fixes its roster at mount (`SET_CURRENT_PLAYER`,
`NEXT_TURN`, `SET_PHASE` only) while `DeckContext` maintains a *separate* `players` list that
grows implicitly on first draw. Two sources of truth. Reconcile them and add
add/remove/reorder actions.

**F7. Joker support end-to-end.** `createStandardDeck({jokers: 2})`, plus the art from B4. Needed
for euchre, canasta, and many rummy variants.

**F8. Deck presets and multi-deck shoes.** `createEuchreDeck`, `createPinochleDeck`,
`createShoe(6)` for blackjack. Currently every example hand-rolls its own filtering.

**F9. Hand and deck utilities.** `sortHand(by)`, `groupBy`, `peek(n)`, `insertAt`,
`drawFromBottom`, and common deal patterns. Each example reimplements these.

**F10. Rank/hand evaluation helpers.** Poker hand ranking and comparison, run/set detection,
blackjack totals with soft aces. The poker, golf, and rummy-style examples each contain their
own copy.

**F11. Serialization and hydration.** `serialize(state)` / `hydrate(snapshot)` for save-resume
and for the WebSocket/Supabase multiplayer flows the examples document. Requires F1 for the RNG
seed to round-trip.

**F12. Undo/redo history.** A history middleware over `DeckContext` — valuable for solitaire and
for debugging.

### Rendering and components

**F13. Interactive primitives.** Every interactive example hand-rolls cursor state, bounds
checking, and `useInput` wiring. Ship a `useCardCursor` hook and/or a `<Hand>` component with
built-in selection, focus, and keyboard navigation. This is also the natural home for a real
`onClick`/`onSelect` (see B11).

**F14. Global theming and accessibility.** Colors are hardcoded (`red`/`white`) at the component
level. Add a theme provider covering suit colors, border style, and custom suit glyphs, plus a
monochrome/no-color mode for dumb terminals and colorblind-safe palettes.

**F15. Responsive variant selection.** Auto-pick `minimal`/`mini`/`simple`/`ascii` from
`useStdout().stdout.columns` so layouts degrade gracefully instead of wrapping.

**F16. Animation and transitions.** Deal, flip, and move animations — the single most requested
kind of polish for a terminal card library, and the reason `effects` exists on `BaseCardProps`.

**F17. Export layout primitives.** `CARD_DIMENSIONS`, suit symbol maps, and `defaultBackArtwork`
are internal, so anyone writing a custom card component has to re-derive them.

**F18. `CardGrid` support for custom and tarot cards.** `GridCard` is standard-cards-only, unlike
`CardStack`. Blocks grid layouts for Uno/MTG/tarot. Pairs with B18.

**F19. `CardFan` component.** Arc/fan layout for a held hand — the one classic presentation the
library has no primitive for.

**F20. Richer tarot support.** Actually invert the art when `reversed` (today it only changes the
type line text), add spread layouts (three-card, Celtic Cross), and a tarot `MiniCard`.

### Project health and content

**F21. Test infrastructure.** Fix the ava config (B5, B6), add coverage reporting, and add unit
tests for the currently untested `utils/text.ts`, `utils/layout.ts`, and `utils/cardArtRenderer.ts`
— the modules with the most subtle arithmetic (B19). Consider whether vitest gives a better
snapshot story than ava for component output.

**F22. Regression tests for this audit.** Specifically: event-dispatch-count assertions (B2),
hook-outside-provider assertions (B3), a joker render test (B4), a `createPairedDeck` adjacency
test (B8), and a `npm pack` contents assertion (B7).

**F23. Repo hygiene.** Missing: `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`,
`.github/ISSUE_TEMPLATE/`, `.github/PULL_REQUEST_TEMPLATE.md`, `.github/dependabot.yml`. Also
`.release-it.json` writes `changelog.md` but no changelog is committed to the repo.

**F24. New game examples.** Cribbage, hearts, spades, rummy, euchre, crazy eights, durak,
president. Each exercises mechanics the current 22 examples do not (pegging, trick-taking with
trump, melding, attack/defend).

**F25. Docs site content** (`ink-playing-cards-www`). Generated API reference from the TypeScript
declarations, and live/recorded terminal demos per component rather than static code blocks.
